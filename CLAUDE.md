# CLAUDE.md

The ROS 2 package `syncai_robot_3d_mapping`, written in Rust (`rclrs` 0.8). It is currently a
skeleton node (`syncai_robot_3d_mapping`, executable `mapping_node`) that publishes a
`std_msgs/String` heartbeat; the 3D mapping pipeline will grow from here. Layout and conventions are
copied from SyncAI-Robot-State (`~/Projects/SyncAI-Robot-State`), which is the reference for rclrs
patterns.

**The repo root is the package itself** (`package.xml` and `Cargo.toml` are at the root).
`.devcontainer/` is only for developing this repo on its own. There is no Makefile or
docker-compose.

## Build and test

Everything runs in the Dev Container `syncai-robot-3d-mapping` (VS Code Reopen in Container, or
`devcontainer up --workspace-folder .`). `/workspace` is the named volume
`syncai-robot-3d-mapping_workspace`, and this repo is mounted at
`/workspace/src/syncai_robot_3d_mapping`. The host has no ROS: only `cargo fmt` works there.

```bash
docker exec syncai-robot-3d-mapping bash -lc 'cd /workspace && colcon build --symlink-install --packages-select syncai_robot_3d_mapping'
docker exec syncai-robot-3d-mapping bash -lc 'cd /workspace/src/syncai_robot_3d_mapping && cargo fmt --check'
docker exec syncai-robot-3d-mapping bash -lc 'cd /workspace/src/syncai_robot_3d_mapping && cargo clippy --target-dir /workspace/build/.clippy --all-targets'
docker exec syncai-robot-3d-mapping bash -lc 'cd /workspace/src/syncai_robot_3d_mapping && cargo test --target-dir /workspace/build/.clippy'
```

- `cargo` commands need one `colcon build` first: `/workspace/.cargo/config.toml` is generated by
  colcon-ros-cargo.
- Warnings from `/opt/ros2_rust_underlay/...` (rclrs itself) are not ours; ignore them, as well as
  cargo's "Patch `<pkg>` was not used in the crate graph" notices.
- Before finishing, build / clippy / fmt must have zero warnings and all unit tests must pass.
- CI (`.github/workflows/ci.yml`) runs `cargo fmt --check` on the bare runner and
  `.github/scripts/ci.sh` (colcon build, `clippy -- -D warnings`, test) inside the image built from
  `.devcontainer/Dockerfile`. Keep the script and this list in step.
- Stop a test node with `pkill -x mapping_node` (not `-f`, which also kills the `docker exec` shell).

## Architecture (`src/mapping_node/`)

| File | Responsibility |
| --- | --- |
| `mod.rs` | Wiring: parameters → publisher → one worker → heartbeat timer |
| `parameters.rs` | The load-time (read-only) parameters, and Hz -> period |

Logic that can be expressed over plain Rust types goes in pure functions with unit tests; convert
ROS messages at the boundary so tests need no ROS environment. Keep everything on ONE `Worker`
unless a callback blocks.

## rclrs pitfalls

- **Params YAML keys do not expand wildcards**: only `/**` or the node's full name match, so the
  params file uses `/**:`.
- **Worker = callback group**: callbacks from `worker.create_*` run with `&mut Payload`.
- **Log macros take `&Logger`**: write `log_warn!(&self.logger, ..)`.
- **`Arc::from(s)` in a parameter builder is ambiguous**: use `Arc::<str>::from(s)`.
- **No SIGINT handler**: Ctrl-C ends the process without running `Drop`.
- **`ros-env` versions**: this package uses `ros-env` 0.2 while rclrs uses 0.3 internally; their
  message types are incompatible, so do not use rclrs helpers that return message types.
- Message packages go in `<depend>` in `package.xml`, not in `Cargo.toml`; without it
  `ros_env::<pkg>` does not exist.
- The Dockerfile sets `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=fallback` so the pinned Rust 1.85
  toolchain keeps building rclrs; `clippy.toml` (`msrv`) and `rustfmt.toml` are written for 1.85.
- `launch/` and `params/` are installed to share via `[package.metadata.ros] install_to_share`.

## Conventions

- Everything is written in English (code, comments, logs, docs). Log messages carry a `[Module]`
  prefix (e.g. `[MappingNode]`, `[Parameters]`).
- Formatting follows `rustfmt.toml` (max_width 100); `Cargo.toml` enables `unsafe_code = "forbid"`
  and `clippy::all`.
- Commits use Conventional Commits (`.github/prompt/copilot-commit-message-instructions.md`), in
  English.
